## Local response timing correction

The existing UI could show an old verification response after the candidate was
edited during its request. Although acceptance and download were hidden for a
changed source, the old result panel could misleadingly show a passing verdict.

Every edit or candidate change now invalidates the request revision. Late success
and error responses are ignored, including edit-then-restore of the exact same
text. The verify button becomes available again when the pending request settles.

Run `node --test tests/ui_race.test.cjs` to exercise the actual application handlers
with delayed mock HTTP responses. Five checks cover editing, switching fixtures,
editing/restoring, late network failure, and the unchanged successful journey.
These are local handler tests, not a deployed browser network-race reproduction.

The correction is isolated on `fix/ui-verification-race`. The source checkout
contained concurrent MongoDB integration edits, which were preserved untouched.
The observed hosted preview predates this correction. No deployment occurred.
